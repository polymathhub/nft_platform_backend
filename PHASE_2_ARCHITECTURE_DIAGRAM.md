## 🔐 Authentication & Authorization

```
┌─────────────────────────────────────────────────────────────────────┐
│ REQUEST LIFECYCLE                                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                       │
│ 1. FRONTEND: User interacts with mint.html                          │
│    └─ window.Telegram?.WebApp?.initData available                   │
│                                                                       │
│ 2. API CALL: Frontend sends request                                 │
│    ├─ telegramFetch('./js/telegram-fetch.js')                       │
│    │  └─ Adds X-Telegram-Init-Data header                           │
│    │                                                                  │
│    └─ Fallback: Direct fetch with header                            │
│       └─ If module import fails                                     │
│                                                                       │
│ 3. REQUEST HEADERS:                                                  │
│    POST /api/v1/blockchain/nft/prepare-mint HTTP/1.1                │
│    Content-Type: application/json                                   │
│    X-Telegram-Init-Data: {signed_data_from_telegram}                │
│    │                                                                  │
│    │ Example init data (URL-encoded):                               │
│    │ query_id=AA...Ab&user=%7B%22id%22:123...%7D&...&hash=ABC...   │
│                                                                       │
│ 4. BACKEND: Middleware Verification                                 │
│    ├─ Extract X-Telegram-Init-Data header                           │
│    ├─ Parse as URL-encoded: user={id, ...}, hash=...               │
│    ├─ Reconstruct original string (without hash)                    │
│    ├─ HMAC-SHA256: crypto.subtle.sign(                              │
│    │    "SHA256",                                                    │
│    │    bot_token_hash,  ← SHA256(TOKEN)                            │
│    │    init_data_string                                            │
│    │  )                                                              │
│    ├─ Compare: computed_hash == provided_hash                       │
│    │  └─ If mismatch: REJECT with 401                               │
│    │                                                                  │
│    └─ Extract: user["id"] = 123456789                               │
│       └─ Use as get_current_user dependency                         │
│                                                                       │
│ 5. ENDPOINT PROTECTION:                                              │
│    @router.post("/nft/prepare-mint")                                │
│    async def prepare_nft_mint(                                      │
│        request: PrepareMintRequest,                                 │
│        current_user: User = Depends(get_current_user)  ← VERIFIED   │
│    )                                                                 │
│                                                                       │
│ 6. RESPONSE:                                                         │
│    ├─ If verified: Process request, return 200 + data               │
│    ├─ If invalid: Return 401 Unauthorized                           │
│    └─ If error: Return 500 + error message                          │
│                                                                       │
└─────────────────────────────────────────────────────────────────────┘
```

**Security Properties**:
- ✅ Stateless: No tokens, sessions, or cookies stored
- ✅ Cryptographically verified: HMAC-SHA256 signature
- ✅ Per-request: Fresh verification on every API call
- ✅ Scalable: Works across multiple servers/load balancers
- ✅ Telegram-managed: Private keys handled by Telegram

## 📊 Database Schema (Phase 2 Models)

```sql
-- TON Wallet Sessions (Multi-device tracking)
CREATE TABLE ton_wallet_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id BIGINT NOT NULL REFERENCES users(telegram_id),
  wallet_address VARCHAR(255) NOT NULL,
  public_key VARCHAR(88),  -- Base64 BOC
  chain VARCHAR(20),  -- "mainnet" | "testnet"
  session_hash VARCHAR(255) UNIQUE NOT NULL,  -- Replay prevention
  device_platform VARCHAR(50),  -- iOS, Android, Web
  device_name VARCHAR(255),
  app_name VARCHAR(50),
  is_active BOOLEAN DEFAULT true,
  transaction_count INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW(),
  last_activity_at TIMESTAMP DEFAULT NOW(),
  expires_at TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(telegram_id),
  INDEX (user_id),
  INDEX (wallet_address),
  INDEX (session_hash)
);

-- Blockchain Transactions (On-chain verification)
CREATE TABLE blockchain_transactions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id BIGINT NOT NULL REFERENCES users(telegram_id),
  nft_id UUID REFERENCES nfts(id),
  transaction_hash VARCHAR(255) UNIQUE NOT NULL,
  contract_address VARCHAR(255) NOT NULL,
  payload_boc TEXT,  -- Base64-encoded BOC
  
  status ENUM('pending', 'in_progress', 'confirmed', 'failed'),
  confirmations INTEGER DEFAULT 0,
  trust_level INTEGER DEFAULT 0,  -- 0-10 scale
  exit_code INTEGER,  -- Smart contract result
  
  verified_at TIMESTAMP,
  verification_attempts INTEGER DEFAULT 0,
  last_verification_at TIMESTAMP,
  
  tx_metadata JSONB,  -- Custom metadata (renamed from "metadata")
  error_message TEXT,
  
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(telegram_id),
  INDEX (user_id),
  INDEX (transaction_hash),
  INDEX (status),
  INDEX (nft_id),
  INDEX (contract_address)
);

-- NFT Updates (Link to blockchain)
ALTER TABLE nfts ADD COLUMN (
  blockchain_transaction_id UUID REFERENCES blockchain_transactions(id),
  blockchain_data JSONB  -- On-chain specific data
);
```
